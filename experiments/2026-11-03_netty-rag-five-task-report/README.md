## 2. 三组与测量设置

| 项目 | 设置 |
|---|---|
| A：无 RAG | 不提供历史参考，复用经提示词及补丁指纹核对的已有生成 |
| B：随机参考 | 从与 C 相同的隔离池随机抽取，固定种子，条数相同、参考字节量差≤10% |
| C：有 RAG | 用题目公开说明和源文件类名检索，最多 3 条历史参考 |
| Agent／模型 | Codex CLI 0.161.0；deepseek-v4-pro；high 推理 |
| 每次生成预算 | 最多 20 次请求，1200 秒活跃时间，单请求最多 8192 输出 token |
| 测量对象 | 原版、开发者版、功能检查通过的 A/B/C 补丁；不按速度挑选补丁 |
| 重复设置 | 每版本／场景 5 次独立 JVM；每 JVM 10 次预热＋50 次正式采样，每次 1 秒 |
| 环境 | 同一实验室主机、固定 Docker 镜像、CPU 20/21、2 CPU 配额、3 GiB 内存、无容器换页、JDK 8、堆和 direct 各 512 MiB |
| 调度 | 当前串行；两路、四路并行诊断均未通过干扰门槛，不混入正式结果 |
| 负载 | Benchmark 原有性能测试及冻结参数；不针对生成结果修改负载 |
| 数据选择 | 固定取编号 0–4 的前五轮；此前多出的轮次保留但不混入本表 |

每题每组的 5 次代码生成，与每份补丁的 5 次独立 JVM 测量是两个层次。每场景 250 个正式采样值仍只有 5 个独立 JVM，不按 250 个独立样本计算区间。b72fea3 的首份补丁验收与其余补丁分两个测量阶段，各自匹配同阶段原版，均保留前五轮。

## 4. 速度结果

以下是已通过功能检查补丁的描述性汇总：先将每轮性能除以同轮原版，统一为加速比，再对五轮、补丁及该题场景取几何平均。**1.00× 为持平，1.20× 表示同样工作约快 20%（耗时约减少 16.7%）。** 未产出补丁的生成不填造性能值，其次数保留在上表。

| 题目 | 开发者版相对原版 | 无 RAG | 随机参考 | 有 RAG |
|---|---:|---:|---:|---:|
| `2791f0f` | 2.030× | 1.922× | 1.868× | 1.959× |
| `b72fea3` | 1.231× | 1.246× | 1.180× | 1.187× |
| `dd69a81` | 1.157× | 1.113× | 1.154× | 1.132× |
| `9abeaf1` | 1.234× | 1.253× | 1.159× | 1.194× |
| `feb804d` | 0.994× | 1.013× | 0.996× | 0.992× |

b72fea3 开发者版一栏对两个阶段等权汇总；补丁仍只与其自身阶段原版比较。

- 定时任务编号分配：三组均有明显加速，有 RAG 的描述性均值略高，尚不能据此认定组间差异显著。
- 月份解析、事件循环唤醒：无 RAG 的平均加速比高于有 RAG。
- HTTP 地址处理：随机参考平均加速比较高，但各组可测补丁数不同。
- 跨线程定时任务：三组整体速度接近原版，有 RAG 未显示整体速度优势。

**当前可报告：三组都能产生有效优化；尚无一致证据表明有 RAG 在这五题全面优于无 RAG。** 这是已完成五题的阶段观察，不能作为全部题库或 RAG 一般有效性的最终结论。

## 6. 不确定性与统计口径

逐补丁／场景的加速比和区间见 [paired-metrics.csv](results/paired-metrics.csv)。以五个配对 JVM 块的 log 加速比计算 t 区间（n=5，df=4，95%）；探索性“加速／变慢”同时要求均值变化超过 5% 且区间不跨 1。区间尚未做多重比较校正，不能当作确认性显著性结论；场景和同题不同补丁也不是独立题目。

没有按第几次生成将 A/B/C 一一配对，也没有完成控制任务和生成差异的正式组间推断。可测补丁汇总存在功能通过选择效应，不能只用该表代替包含失败生成的整体效能评价。

A 组与 B/C 生成日期不同，供应商只提供可变模型别名；配置一致不等于不可变模型权重已被证明一致。当前是带资源采集器的原生 JMH 测量，不冒充官方无采集器总分。

## 7. RAG 知识库规模与构建

| 层次 | 内容与规模 |
|---|---|
| 全量原始材料整理库 | 588 个不同提交，1,147 个测试场景记录 |
| 可追溯内容 | 587 份补丁、575 份生产源码文本、587 份性能测试源码 |
| 功能状态 | 510 个提交有功能检查通过记录 |
| 全量检索索引 | 8,201 个文本块 |
| 本轮隔离后的参考池 | 297 个提交，2,872 个完整生产代码差异块卡片 |
| 每题给模型的参考 | 最多 3 条；单条≤6,000 字节，总参考上下文≤18,000 字节 |

构建流程：

1. 只读提取历史云端和实验室归档，按提交 SHA 建条目，关联 PR／说明、修改前后材料、项目已有测试、性能观察值、功能状态和证据指纹。原始文件不覆盖、不删除。
2. 保存真实零值、退化、不确定及缺失；588 份材料不等于 588 个已确认优化。已有源码与负载关系审查状态随条目保留。
3. 将补丁按完整生产差异块切成参考卡片，保留标题／问题、代码改动、测试信息和性能摘要；过长块在建索引时排除并记录，不静默截断代码块。
4. 全局排除已知答案提交、官方 PR 关联及相关版本、重复改动、答案 SHA／PR 显式引用、功能证据不足或无法装入长度预算的材料；每题再隔离同目标生产文件。全部原始材料仍保留。
5. 用公开题目说明＋目标类名构造查询，BM25 权重为问题文本 3、代码 2、测试名 1，分数越小越靠前；数值性能结果不参与排序。相关性门槛、去重、排序和长度规则统一自动执行，无逐题人工指定。
6. B 组在同一隔离池固定种子随机抽取，匹配条数和字节量；C 组按排序选取。生成开始前一次性提供参考，不是在 Agent 运行途中反复检索。

该实验是回顾性检索，不声称只使用目标提交发生前公开的历史材料。已知答案隔离降低泄漏风险，但没有证明完全不存在语义近似答案；召回率、准确率尚无独立金标准。

## 8. RAG 过程记录与实际采用

本目录 [retrieval/](retrieval/) 留存五题的查询、候选排名、原始评分、排除原因、随机种子及 B/C 完整参考正文。已核对这五题 B/C **50 次实际生成记录**的参考文本 SHA 与本目录正文完全一致；三组共同变量的真实请求检查记录另附。

**已知给了模型什么，不等于已知模型采用了什么。** 是否借用具体参考仍需结合补丁和执行轨迹逐份审查；没有可靠证据的保持“未确认采用”，不能从检索命中直接认定找到答案。
