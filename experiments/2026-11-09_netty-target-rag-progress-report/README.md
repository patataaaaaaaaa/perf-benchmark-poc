# Netty 目标感知 RAG 实验阶段汇报

数据快照时间 2026-11-09T17:50:34+08:00。

## 实验目的与范围

在 BenchLLMRealSE 的 18 道 Netty 性能优化题上，分别以时间、CPU、内存为优化目标检索历史性能案例，生成固定补丁，经功能检查后测量性能。当前15道已进入生成，45个任务目标组合均已完成生成尝试；13道已结批，2道仍在正式测量，3道存在评测环境阻塞。

截至快照，12道至少一个目标已验收5个区组，5道三个目标均验收5个区组。结批包括空补丁和功能失败，不能将结批数作为优化成功数。

## 实验结果怎么读

先看补丁能否改善它被要求优化的指标。速度行用提速补丁，CPU 行用省 CPU 补丁，堆分配行用省分配补丁。每行都与原版、开发者、GPT 分别比较。

|目标及实测指标|与原版比|与开发者版比|与 GPT 比|
|---|---:|---:|---:|
|速度|6 / 1 / 1|2 / 1 / 5|1 / 3 / 4|
|每次操作的 CPU 时间|9 / 0 / 2|4 / 1 / 6|4 / 4 / 2|
|每次操作的堆分配量|6 / 1 / 1|3 / 2 / 3|0 / 5 / 2|

表中每格依次是 **改善 / 接近 / 退化的题数**。每道题只算一次。将相对该对照改善超过 1% 记为改善，退化超过 1% 记为退化，其余记为接近。1% 是方便阅读的描述性分组，未做显著性检验。只比较双方都测满 5 个区组的题目，各列分母可不同。

- **目标补丁对原版常有改善，对 GPT 的优势随指标而变。** 提速补丁在 8 道可比题中有 6 道比原版快超过 1%，对 GPT 则只有 1 道快超过 1%。CPU 目标在部分题上有较大收益，例如 `2ed95c9` 的省 CPU 补丁相对原版减少了约 45% 的 CPU 时间。堆分配方面，可与 GPT 对照的题目未出现新 RAG 再省超过 1% 的例子。
- **同一补丁的效果会随负载反转。** `87ec2f8` 的提速补丁在 40 个场景汇总后比原版快 42.8%。单看 `decodeString`，DIRECT 缓冲区、UTF-8、1024 字节时吞吐提高 300.6%，而 HEAP 缓冲区、US-ASCII、10240 字节时吞吐下降 60.1%。这道题上 GPT 的汇总提速为 42.6%，二者接近。
- **相对旧 RAG 也能看到取舍。** `b72fea3` 的提速补丁在两个日期输入上，相对旧 RAG 吞吐都提高约 5%。同题省 CPU 补丁在两个输入上的 CPU 时间均增加约 21%。这两个目标各生成了一份补丁。旧 RAG 对照取同题有效 C 组补丁均值，逐场景差异见[旧 RAG 对照数据](scenario-results.csv)。

## 检索与生成方法

- 知识库原始材料为588个提交、1147个场景。整理计算各场景的时间、CPU与内存改善百分比，保留退化和缺失记录。203个有完整材料的案例参与检索，包含106个长案例。
- 修改块分别编码，长块分段。使用固定版本 BAAI/bge-base-en-v1.5；每个commit以最高片段余弦相似度作为相关性。去重后取最多40个commit，并要求相似度至少0.45。
- 按当前目标计算场景改善率，先统一为越大越好，再对同一commit取最大改善。候选内将性能转换为0～1代价，排序分为0.2×相似度−0.4×代价，选最多3个commit。该权重为固定实验设置，尚未做权重消融。
- 注入所选commit的完整案例、全部已有性能记录、计算结果和排序依据。超过CLI提示容量的案例改为完整文件读取，记录模型实际收到的可核验去重字节下限。投递方式在逐题表中标明。
- 生成使用 Codex CLI 0.161.0、deepseek-v4-pro、high。每题每目标1份r0，每份最多20次模型请求和1200秒；修复续跑沿用原会话与累计账本。5个性能区组均使用同一份固定补丁。

## 评测设置

性能测试在原实验室服务器串行运行。固定Docker镜像 sha256:8f27ad86a2fa6bd295ecddb25cee4bef208ca00359f8c24a8536778b753ed1f6，JDK8，CPU核心20/21、2核配额。常规题内存3GiB，87ec2f8沿用原生8GiB堆和12GiB容器。每场景每区组1 fork、10次预热、50次正式测量，每次1秒；保留原生方法、参数与模式。

先编译和运行指定功能测试，通过后每份补丁测满5区组。时间记录原生耗时或吞吐量，CPU记录每操作CPU时间，memory记录每操作堆分配量。83a19d5采用SampleTime，直方图按采样次数加权验收；其原版5个正式区组需要在同批补齐。67d3a78使用经验证的JMH1.12兼容采集器，保留兼容来源。

## Chat baseline 与可比性

直接Chat基线输入题目、源码、指定单元测试和benchmark，单次回答生成补丁，无工具执行、RAG或测试反馈迭代。模型标记GPT-6 High（用户报告，未独立核实）。正式测完12题、13份补丁，2791f0f有两份输出，共94个补丁×场景。探索性配对区间统计相对Original为55改善、8退化、31不确定；相对Developer为9改善、50退化、35不确定。该统计来自用户提供的已核验结果。

Chat正式测完的12题中，新RAG已有11题至少一个目标完成5区组；8a8337e三个目标为空补丁。性能测试采用同机固定镜像与资源约束，但测量日期不同；GPT单次Chat与DeepSeek Agent的模型和工具流程同时变化，因此该对照反映方案整体表现。新旧RAG采用同一生成模型和请求上限，完整文件读取、续跑修复及不同生成重复数仍需在比较中标明。Chat的94个场景不能按独立题目统计，存储读写均为0也不能作为I/O改善证据。
