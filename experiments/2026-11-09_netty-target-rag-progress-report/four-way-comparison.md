# Netty 四版本结果对照

数据快照为 2026-11-09 17:50（北京时间）。18 道题中，12 道至少一份新 RAG 补丁已完成正式测量。其中 11 道同时有原版、开发者、GPT 和至少一份新 RAG 的数据。下表覆盖所有已有正式数字的题目，其余题目及失败原因见[逐题状态](README.md#逐题与目标状态)。

## 先看每个目标达到了什么效果

|目标及实测指标|新 RAG vs 原版|新 RAG vs 开发者版|新 RAG vs GPT|开发者版 vs GPT（12 题）|
|---|---:|---:|---:|---:|
|速度|6 / 1 / 1|2 / 1 / 5|1 / 3 / 4|6 / 3 / 3|
|每次操作的 CPU 时间|9 / 0 / 2|4 / 1 / 6|4 / 4 / 2|6 / 2 / 4|
|每次操作的堆分配量|6 / 1 / 1|3 / 2 / 3|0 / 5 / 2|4 / 5 / 3|

表中每格依次是 **改善 / 接近 / 退化的题数**。每道题只算一次。将相对该对照改善超过 1% 记为改善，退化超过 1% 记为退化，其余记为接近。1% 是方便阅读的描述性分组，未做显著性检验。只比较双方都测满 5 个区组的题目，各列分母可不同。最后一列以 GPT 为对照，统计开发者版更好、接近、更差的题数，包含两者都完成正式测量的 12 道题。2791f0f 的两份 GPT 补丁在各指标上给出一致的分组，该题计一次。

- **目标补丁对原版常有改善，对 GPT 的优势随指标而变。** 提速补丁在 8 道可比题中有 6 道比原版快超过 1%，对 GPT 则只有 1 道快超过 1%。CPU 目标在部分题上有较大收益，例如 `2ed95c9` 的省 CPU 补丁相对原版减少了约 45% 的 CPU 时间。堆分配方面，可与 GPT 对照的题目未出现新 RAG 再省超过 1% 的例子。
- **同一补丁的效果会随负载反转。** `87ec2f8` 的提速补丁在 40 个场景汇总后比原版快 42.8%。单看 `decodeString`，DIRECT 缓冲区、UTF-8、1024 字节时吞吐提高 300.6%，而 HEAP 缓冲区、US-ASCII、10240 字节时吞吐下降 60.1%。这道题上 GPT 的汇总提速为 42.6%，二者接近。
- **相对旧 RAG 也能看到取舍。** `b72fea3` 的提速补丁在两个日期输入上，相对旧 RAG 吞吐都提高约 5%。同题省 CPU 补丁在两个输入上的 CPU 时间均增加约 21%。这两个目标各生成了一份补丁。旧 RAG 对照取同题有效 C 组补丁均值，逐场景差异见[旧 RAG 对照数据](scenario-results.csv)。

## 计算与比较范围

同一场景先取 5 个区组的均值。速度倍数取吞吐比或耗时的倒数比，CPU 和堆分配的改善倍数取原版用量除以补丁用量。同题多场景按倍数等权取几何平均，得到 R。速度提高百分比为 (R − 1) × 100%，CPU 时间或堆分配节省百分比为 (1 − 1/R) × 100%。逐题对 GPT、开发者的比较直接用该对照作分母。

同一场景采用匹配的评测配置，各版本测量日期不同。Chat 与新 RAG 的生成模型、工具和上下文也不同，结果比较的是两套完整方案。每个新 RAG 目标仅有一份固定补丁，三个指标的可测题集也不同。空补丁和功能失败单列，未计入性能比较。

不同目标补丁对其他指标的影响，可在[完整场景 CSV](four-way-scenes.csv)中查看。文件按题目、方法、参数、模式和指标逐行列出三份补丁全部可用的测量值。
